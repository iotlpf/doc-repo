01背景与目标

Aura 是一款多模态数据处理引擎，由 AI DataLake 服务在华为云容器引擎 CCE上自动部署和管理。AI DataLake 服务提供管控面，负责自动创建 CCE 容器集群、安装 Aura 引擎、调度数据处理作业等全生命周期管理。在凭证管理层面，我们面临两类典型场景：

  • 云上场景（AI DataLake + 华为云 CCE）：AI DataLake 管控面运行在华为云上，自动管理 CCE 集群和 Aura 引擎。用户在 AI DataLake 平台上完成授权配置后，AI DataLake 负责将授权信息自动下发并绑定到作业 Pod，用户只需提交作业。云上授权基于华为云 CCE 的 OIDC 工作负载身份机制（对标 AWS IRSA），通过 IAM 身份提供商 + 信任委托（Agency）实现。
  • 本地 SDK 场景：用户在本地开发机或私有数据中心安装 Aura Python SDK，直接调用引擎，需要自行管理 AK/SK 的创建、存储、轮转与有效期。

本文档的目标是：调研 AWS / GCP / Azure 等业界标准方案；给出云上场景（AI DataLake + 华为云 CCE）的完整设计；给出本地 Python SDK 场景的完整设计；设计 Aura Python SDK 的统一凭证抽象层和 AuraClient 类设计，覆盖凭证获取失败、长时作业 Token 过期等异常场景；给出安全设计与实施路线图。

核心设计原则

用户代码中永远不出现长期有效的静态密钥。云上通过华为云 CCE OIDC 工作负载身份消除密钥，AI DataLake 管控面自动完成身份绑定和权限下发；本地通过 Python SDK 托管的 AK/SK 自动轮转将密钥暴露面降到最低。SDK 默认行为即安全最佳实践。

02术语定义

术语定义
AI DataLake云服务，提供管控面，负责自动创建华为云 CCE 集群、安装 Aura 引擎、调度作业、管理授权配置等。
华为云 CCECloud Container Engine，华为云容器引擎，Aura 引擎和作业运行的基础设施（对标 AWS EKS）。由 AI DataLake 管控面自动创建和管理。
OIDC 身份提供商华为云 IAM 中的资源，将 CCE 集群注册为受信任的 OIDC 提供商，上传集群 JWKS 公钥用于验证 ServiceAccount Token。对标 AWS IAM OIDC Provider。
信任委托（Agency）华为云 IAM 中的委托关系，通过信任策略指定受信任的 OIDC 提供商和条件，被委托后可获取临时安全凭证。对标 AWS IAM Role。
AssumeAgencyWithOIDC华为云 IAM STS v5 API，使用 OIDC ID Token 换取临时安全凭证（AK/SK + security_token）。对标 AWS AssumeRoleWithWebIdentity。

ServiceAccount TokenCCE 通过 TokenRequest API 签发的短期 JWT，通过 Projected Volume 挂载到 Pod，默认 1h 有效，kubelet 自动轮转。
AK/SKAccess Key / Secret Key，长期有效的对称密钥对，用于签名认证。
Credential Provider凭证提供者，SDK 中负责从特定来源获取凭证的组件。
Provider Chain凭证提供者链，按优先级依次尝试多个 Provider，首个成功即返回。

03场景定义与核心挑战

3.1 云上场景（AI DataLake + 华为云 CCE）

AI DataLake 服务提供管控面，自动在华为云 CCE 上创建集群、安装 Aura 引擎。用户在 AI DataLake 平台上完成授权配置后，AI DataLake 管控面负责在 CCE 中完成 ServiceAccount 创建、IAM 身份提供商配置、信任委托绑定等操作，并将身份自动注入到作业 Pod 中。核心诉求：用户在 AI DataLake 平台完成授权配置后提交作业即可；作业 Pod 的代码和镜像中不包含任何密钥；凭证自动获取、自动刷新；AI DataLake 直接使用华为云 CCE 提供的 OIDC 相关能力，不自行实现 Webhook 等基础设施。

3.2 本地 SDK 场景

用户在本地开发机、CI/CD Runner 或私有数据中心安装 Aura Python SDK，直接调用引擎。用户需自行创建和管理 AK/SK；AK/SK 有明确的有效期，需要定期轮转；SDK 应尽可能降低用户管理凭证的心智负担。

3.3 核心挑战

04友商标准方案调研

4.1 AWS 凭证体系全景

AWS 构建了业界最完整的工作负载身份体系，核心思想是"优先使用短期凭证，消除长期密钥"。整个体系分为四个层次：

图 2：AWS 凭证体系四大场景全景

4.1.1 容器内工作负载：IRSA

IRSA 是 AWS EKS 中为 Kubernetes Pod 授予 IAM 权限的标准机制，基于 OIDC 联邦。这是华为云 CCE OIDC 工作负载身份的直接对标方案——华为云通过 IAM 身份提供商 + 信任委托 + AssumeAgencyWithOIDC API 实现等价能力。

4.1.2 非 AWS 环境：IAM Roles Anywhere

使用 X.509 客户端证书替代长期 AK/SK，适用于有 PKI 体系的企业本地高级场景。

4.1.3 密钥管理与轮转：Secrets Manager

对于无法消除的密钥，提供托管存储与自动轮转：KMS 加密、版本管理、Lambda 轮转函数（四步协议）、最短 4 小时轮转。

4.1.4 SDK 凭证解析与配置文件

AWS SDK 通过 Credential Provider Chain 按顺序解析凭证来源。配置文件采用双文件方案：~/.aws/credentials（仅存 AK/SK）和 ~/.aws/config（存 region 等非凭证参数）。这是 Aura Python SDK 配置文件方案的直接参考。

4.2 GCP / Azure / SPIFFE 简要对比

GCP Workload Identity Federation 支持任意 OIDC/SAML 外部身份源；Azure Workload Identity 在 AKS 中通过 OIDC 联邦凭据将 K8s SA 关联到 Entra ID Application；SPIFFE/SPIRE 是 CNCF 毕业的工作负载身份开放标准。三大云厂商已收敛到同一范式：OIDC Workload Identity 作为云上首选，SDK 通过 Provider Chain 统一所有来源，配置文件采用 credentials + config 双文件分离。

05云上场景设计（AI DataLake + 华为云 CCE）

5.1 架构定位与信任模型

AI DataLake 是一个云服务，提供管控面，负责自动创建华为云 CCE 集群、在集群中安装 Aura 引擎、调度用户作业、管理授权配置。Aura 引擎运行在 AI DataLake 管控面创建和管理的 CCE 集群之上。

整个云上场景的信任模型概括为"用户授权配置 → AI DataLake 管控面自动下发 → 作业 Pod 自动获证"三段式：

  1. 用户授权配置：用户在 AI DataLake 平台上配置授权信息（指定要访问的云资源和权限级别）。AI DataLake 将 IAM 信任委托（Agency）+ 信任策略的配置作为服务操作暴露给用户。
  2. AI DataLake 管控面自动下发：AI DataLake 收到用户配置后，自动完成：在华为云 IAM 中创建/更新 OIDC 身份提供商（上传 CCE 集群 JWKS 公钥）、创建/更新信任委托（Agency）及信任策略、在 CCE 中创建专用 ServiceAccount、配置 Pod 的 Projected Volume。
  3. 作业 Pod 自动获证：用户提交作业后，AI DataLake 在 CCE 中拉起作业 Pod，CCE 通过 TokenRequest API 签发短期 JWT 并挂载到 Pod；Aura Python SDK 读取 JWT，调用华为云 IAM STS 的 AssumeAgencyWithOIDC 接口换取临时 AK/SK，访问 OBS 等云资源。
关键定位

AI DataLake 管控面是 CCE 的使用者和编排者，不是 OIDC 基础设施的实现者。我们直接使用华为云 CCE 提供的 OIDC Issuer、TokenRequest API、Projected Volume 等内置能力，只需要按照使用原理进行配置，不需要自行开发和部署 Webhook 等组件。

5.2 华为云 CCE OIDC 工作负载身份原理

5.2.1 整体流程

① 获取 CCE 集群 JWKS 公钥 → ② IAM 创建 OIDC 身份提供商 → ③ 创建信任委托(Agency) → ④ CCE 创建 SA + 挂载 Token → ⑤ SDK 调 AssumeAgencyWithOIDC → ⑥ 获得临时 AK/SK

5.2.2 关键组件说明

组件华为云 CCE 实现对标 AWS
OIDC 身份提供商在 IAM 中创建，协议选 OpenID Connect，上传 CCE 集群 JWKS 公钥，配置客户端 ID（audience）和身份转换规则IAM OIDC Provider
信任委托（Agency）IAM 中的委托关系，信任策略指定受信任的 OIDC 提供商，限定 oidc:sub 条件；附加身份策略定义权限IAM Role + Trust Policy
凭证交换 APIPOST /v5/agencies/assume-with-oidc，传入 id_token + provider_urn + agency_urn，直接返回临时 AK/SK + security_tokensts:AssumeRoleWithWebIdentity
ServiceAccount Token通过 TokenRequest API 签发，Projected Volume 挂载，audience=客户端 ID，expirationSeconds 可配置EKS Pod Identity Webhook 注入
Token 轮转kubelet 在 Token 超过 24h 或超过 80% 过期时间时自动轮转，Pod 删除时 Token 自动失效kubelet 自动轮转

5.2.3 AssumeAgencyWithOIDC API 详情

这是 Aura Python SDK 在云上场景中调用的核心凭证交换接口：

# 请求
POST https://{iam_endpoint}/v5/agencies/assume-with-oidc
Content-Type: application/json

{
  "provider_urn": "iam::{account_id}:oidcProvider:{provider_name}",
  "agency_urn": "iam::{account_id}:agency:{agency_name}",
  "agency_session_name": "aura-job-{job_id}",
  "id_token": "",
  "duration_seconds": 3600
}

# 响应 (200)
{
  "credentials": {
    "access_key_id": "HSTANO...XBS55JLJ3",
    "secret_access_key": "EoWCQrr...SCcw4Whkt2aXKWAr",
    "security_token": "hQpjbi1XXXXXX...bhBbA0TQ==",
    "expiration": "2026-09-09T12:00:00.000Z"
  },
  "assumed_agency": {
    "urn": "sts::{account_id}::assumed-agency:{agency_name}/{session_name}",
    "id": "{agency_id}:{session_name}"
  }
}
API 关键特性
  • 无需华为云凭证即可调用：调用者身份通过 JWKS 公钥验证 ID Token 签名来确认，不需要预先持有 AK/SK。
  • duration_seconds：默认 3600 秒（1h），取值范围 900~43200 秒（15min~12h），受信任委托的最大会话时长限制。
  • 权限收敛：可通过 policy / policy_ids 参数进一步限制本次会话的权限，最终权限为委托身份策略与会话策略的交集。
  • 旧版 IAM 替代方案：若使用旧版 IAM，需两步走——先调 POST /v3.0/OS-AUTH/id-token/tokens 获取 IAM Token（响应头 X-Subject-Token），再调 CreateTemporaryAccessKeyByToken 换取临时 AK/SK。新版 v5 API 一步到位，推荐使用。

参考：华为云 CCE OIDC 最佳实践 https://support.huaweicloud.com/intl/zh-cn/bestpractice-cce/cce_bestpractice_0333.html ｜ AssumeAgencyWithOIDC API https://support.huaweicloud.com/intl/zh-cn/api-iam5/AssumeAgencyWithOIDC.html

5.3 用户授权配置（AI DataLake 服务化接口）

信任委托（Agency）+ 信任策略的配置由 AI DataLake 以服务操作的形式暴露给用户。用户不需要直接操作华为云 IAM，而是通过 AI DataLake 平台完成：

# 用户通过 AI DataLake API 配置授权（示例）
POST /api/v1/authorizations
{
  "name": "my-data-access",
  "resources": [
    {"type": "obs", "bucket": "my-data-bucket", "permissions": ["read", "write"]}
  ]
}

# AI DataLake 内部自动生成对应的华为云 IAM 配置（用户不可见）
# → 信任委托 Agency 的身份策略：允许 obs:GetObject/PutObject on my-data-bucket
# → 信任策略：信任 OIDC 身份提供商，限定 oidc:sub 为 AI DataLake 专用 SA
# → OIDC 身份提供商：已上传 CCE 集群 JWKS 公钥，audience=aura
用户视角总结

用户只需要做两件事：① 在 AI DataLake 平台配置授权（指定资源和权限）；② 之后直接提交数据处理作业。用户不需要创建 IAM 身份提供商、不需要配置信任委托、不需要了解 OIDC、不需要在代码中写任何凭证。

5.4 AI DataLake 管控面自动下发流程

用户提交授权配置后，AI DataLake 管控面自动完成以下操作：

  1. 确保 CCE 集群就绪：检查 CCE 集群是否已创建（未创建则自动创建）、Aura 引擎是否已安装、集群 OIDC Issuer 是否可用。
  2. 获取并上传 JWKS 公钥：通过 kubectl get --raw /openid/v1/jwks 获取 CCE 集群签名公钥，在华为云 IAM 中创建（或更新）OIDC 身份提供商，上传 JWKS，配置客户端 ID（audience=aura）和身份转换规则。
  3. 创建/更新信任委托（Agency）：在 IAM 中创建专用 Agency，身份策略根据用户授权的资源和权限自动生成；信任策略信任上述 OIDC 提供商，限定 oidc:sub 为 AI DataLake 专用 SA。
  4. 创建/更新 ServiceAccount：在 CCE 的 ai-datalake-system 命名空间中创建专用 SA。
  5. 配置作业 Pod 模板：AI DataLake 拉起作业 Pod 时，自动配置 Projected Volume 挂载 ServiceAccount Token（audience=aura），并注入环境变量。
  6. 记录授权映射：记录"用户授权配置 → Agency → ServiceAccount"的映射关系。

AI DataLake 自动配置的 Pod YAML 关键片段

apiVersion: v1
kind: ServiceAccount
metadata:
  name: aura-job-sa
  namespace: ai-datalake-system
---
# 作业 Pod（AI DataLake 自动生成）
spec:
  serviceAccountName: aura-job-sa
  containers:
  - name: aura-engine
    image: aura-engine:latest
    env:
    - name: AURA_AGENCY_URN
      value: "iam::{account_id}:agency:aura-workload-agency"
    - name: AURA_PROVIDER_URN
      value: "iam::{account_id}:oidcProvider:aura-cce-provider"
    - name: AURA_WEB_IDENTITY_TOKEN_FILE
      value: "/var/run/secrets/tokens/oidc-token"
    - name: AURA_REGION
      value: "cn-east-1"
    volumeMounts:
    - mountPath: "/var/run/secrets/tokens"
      name: oidc-token
  volumes:
  - name: oidc-token
    projected:
      defaultMode: 420
      sources:
      - serviceAccountToken:
          audience: "aura"          # 必须与 IAM 身份提供商的客户端ID一致
          expirationSeconds: 7200   # Token 有效期（秒），可配置
          path: oidc-token

5.5 作业提交与凭证获取

用户提交作业后，凭证获取流程完全自动化：

  1. AI DataLake 调度作业：在 CCE 中创建 Job/Pod，指定 serviceAccountName，配置 Projected Volume 和环境变量。
  2. CCE 签发并挂载 Token：CCE 通过 TokenRequest API 为 SA 签发短期 JWT（audience=aura），通过 Projected Volume 挂载。
  3. SDK 自动获取凭证：Aura Python SDK 初始化时，Provider Chain 检测到 OIDC 环境变量，使用 WebIdentityTokenFileProvider：读取 JWT → 调用 POST /v5/agencies/assume-with-oidc → 获得临时 AK/SK（默认 1h）→ 缓存。
  4. 访问云资源：SDK 使用临时 AK/SK + security_token 对 OBS API 请求签名。
  5. 自动刷新：SDK 后台线程定期检查凭证过期时间，剩余 20% TTL 时自动重新读取 JWT（kubelet 已轮转）并调用 AssumeAgencyWithOIDC 换取新凭证。

5.6 ServiceAccount Token 安全机制

根据华为云 CCE 的 ServiceAccount Token 安全性提升说明，Aura 方案遵循以下安全机制：

安全机制说明Aura 方案中的应用
不再自动创建永久 TokenK8s 1.21+ 使用 TokenRequest API + Projected Volume 获取短期 Token；1.25+ 不再自动创建 SA 对应的永久 SecretAura 作业 Pod 全部使用 Projected Volume 挂载短期 Token，不使用永久 Secret
Token 自动轮转kubelet 在 Token 超过 24h 或超过 80% 过期时间时主动轮转；Pod 删除时 Token 自动失效SDK 每次刷新凭证时重新读取 Token 文件，始终获得 kubelet 轮转后的最新 Token
默认有效期 1hTokenRequest 签发的 Token 默认 1h 有效，可通过 expirationSeconds 配置Aura 配置 expirationSeconds=7200（2h），配合 SDK 后台刷新（20%阈值≈24min）确保持续有效
节点鉴权增强（1.28+）SA 配置注解 rbac.kubernetes.io/restricted-by-node: "true" 后，Token 权限被限定在 Pod 所在节点的资源范围内可选启用，进一步缩小 SA 对集群内资源的访问范围（最小权限原则）
客户端版本要求Python K8s 客户端 >= v12.0.0 才具备证书轮转能力Aura SDK 不直接依赖 K8s 客户端库，仅读取已挂载的 Token 文件，无此限制
集群证书更新注意事项

CCE 集群证书更新后，JWKS 公钥会变化，导致 IAM 侧验签失败。AI DataLake 管控面应监听 CCE 集群证书更新事件，自动重新获取 JWKS 并更新 IAM 身份提供商的签名公钥，避免 OIDC 认证失效。

参考：华为云 CCE ServiceAccount Token 安全性提升说明 https://support.huaweicloud.com/usermanual-cce/cce_10_0477.html

07Aura Python SDK 统一抽象设计

7.1 设计原则

  1. 接口统一：所有凭证来源实现同一接口，上层业务代码无感知；
  2. 链式解析：按优先级依次尝试多个 Provider，首个成功即返回；
  3. 自动刷新：后台线程统一处理凭证过期和刷新；
  4. 失败容错：凭证获取失败时支持主动重试 + 按需刷新，长时作业不中断；
  5. 零配置默认安全：AuraClient(region=...) 即使用默认链；
  6. AWS 标准配置文件：双文件方案（credentials + config），TOML 格式。

7.2 Credential Provider 接口（Python）

from abc import ABC, abstractmethod
from dataclasses import dataclass
from datetime import datetime, timedelta
from typing import Optional
import threading

@dataclass
class AuraCredentials:
    access_key_id: str
    secret_access_key: str
    session_token: Optional[str] = None
    expiration: Optional[datetime] = None

    def is_expired(self) -> bool:
        return self.expiration is not None and datetime.utcnow() > self.expiration

    def is_about_to_expire(self, threshold: timedelta) -> bool:
        return (self.expiration is not None
                and datetime.utcnow() + threshold > self.expiration)

class AuraCredentialsProvider(ABC):
    @abstractmethod
    def get_credentials(self) -> AuraCredentials: ...
    def refresh(self) -> None: pass
    def close(self) -> None: pass

7.4.1 WebIdentityTokenFileProvider（云上 CCE · 华为云 AssumeAgencyWithOIDC）

class WebIdentityTokenFileProvider(AuraCredentialsProvider):
    """云上 CCE 场景：读取 CCE 注入的 OIDC JWT，调用华为云 AssumeAgencyWithOIDC 换取临时凭证"""

    def __init__(self, iam_endpoint: str, refresh_threshold: timedelta = None,
                 max_retries: int = 3, retry_backoff: float = 2.0):
        self._token_file = os.environ.get("AURA_WEB_IDENTITY_TOKEN_FILE")
        self._agency_urn = os.environ.get("AURA_AGENCY_URN")
        self._provider_urn = os.environ.get("AURA_PROVIDER_URN")
        self._iam_endpoint = iam_endpoint
        self._threshold = refresh_threshold or timedelta(minutes=12)
        self._max_retries = max_retries
        self._retry_backoff = retry_backoff
        self._cached: Optional[AuraCredentials] = None
        self._lock = threading.Lock()

    @classmethod
    def is_available(cls) -> bool:
        return all([os.environ.get("AURA_WEB_IDENTITY_TOKEN_FILE"),
                    os.environ.get("AURA_AGENCY_URN"),
                    os.environ.get("AURA_PROVIDER_URN")])

    def get_credentials(self) -> AuraCredentials:
        with self._lock:
            if self._cached is None or self._cached.is_about_to_expire(self._threshold):
                self._cached = self._fetch_with_retry()
            return self._cached

    def refresh(self) -> None:
        """主动刷新：强制重新读取 JWT 并调用 AssumeAgencyWithOIDC"""
        with self._lock:
            self._cached = self._fetch_with_retry()

    def _fetch_with_retry(self) -> AuraCredentials:
        last_exc = None
        for attempt in range(self._max_retries):
            try:
                return self._do_fetch()
            except Exception as e:
                last_exc = e
                if attempt < self._max_retries - 1:
                    wait = self._retry_backoff ** attempt
                    logger.warning("AssumeAgencyWithOIDC attempt %d failed: %s, retry in %.1fs",
                                   attempt + 1, e, wait)
                    time.sleep(wait)
        raise CredentialRefreshError(
            f"AssumeAgencyWithOIDC failed after {self._max_retries} attempts: {last_exc}")

    def _do_fetch(self) -> AuraCredentials:
        # 1. 读取 CCE 挂载的 JWT（kubelet 已自动轮转，每次读取都是最新的）
        with open(self._token_file, "r") as f:
            id_token = f.read().strip()
        # 2. 调用华为云 IAM STS AssumeAgencyWithOIDC
        import requests
        resp = requests.post(
            f"{self._iam_endpoint}/v5/agencies/assume-with-oidc",
            json={
                "provider_urn": self._provider_urn,
                "agency_urn": self._agency_urn,
                "agency_session_name": f"aura-session-{os.getpid()}",
                "id_token": id_token,
                "duration_seconds": 3600,
            },
            timeout=10,
        )
        resp.raise_for_status()
        creds = resp.json()["credentials"]
        return AuraCredentials(
            access_key_id=creds["access_key_id"],
            secret_access_key=creds["secret_access_key"],
            session_token=creds["security_token"],
            expiration=datetime.fromisoformat(
                creds["expiration"].replace("Z", "+00:00")).replace(tzinfo=None),
        )

7.4.2 ConfigFileProvider（本地开发）

class ConfigFileProvider(AuraCredentialsProvider):
    """本地场景：从 ~/.aura/credentials (TOML) 读取 AK/SK，到期前自动轮转"""
    DEFAULT_CREDENTIALS_FILE = os.path.expanduser("~/.aura/credentials")

    def __init__(self, profile="default", credentials_file=None,
                 credential_client=None, rotation_days=7):
        self._credentials_file = credentials_file or self.DEFAULT_CREDENTIALS_FILE
        self._profile = profile
        self._cred_client = credential_client
        self._rotation_threshold = timedelta(days=rotation_days)
        self._cached: Optional[AuraCredentials] = None
        self._lock = threading.Lock()
        self._rotation_in_progress = False

    def get_credentials(self) -> AuraCredentials:
        with self._lock:
            if self._cached is None:
                self._cached = self._load_from_file()
            if (self._cached.expiration is not None
                    and self._cached.is_about_to_expire(self._rotation_threshold)
                    and not self._rotation_in_progress):
                self._trigger_rotation_async()
            return self._cached

    def _load_from_file(self) -> AuraCredentials:
        import tomllib
        with open(self._credentials_file, "rb") as f:
            data = tomllib.load(f)
        prof = data.get(self._profile, data.get("default", {}))
        return AuraCredentials(
            access_key_id=prof["access_key_id"],
            secret_access_key=prof["secret_access_key"],
            expiration=prof.get("expiration"))

7.8 凭证获取失败与异常场景处理

7.8.1 异常场景分类

异常场景触发原因影响
后台刷新线程未及时刷新线程调度延迟、GIL 阻塞、刷新请求超时凭证已过期但缓存未更新，后续 API 请求返回 401/403

AssumeAgencyWithOIDC 调用失败IAM/STS 服务不可用、网络抖动、JWT 验签失败（集群证书更新）、Agency 配置错误无法获取新凭证，旧凭证过期后完全不可用
JWT Token 文件未更新kubelet 轮转异常、Volume 挂载问题读取到已过期的 JWT，AssumeAgencyWithOIDC 返回 400/403
本地 AK/SK 轮转失败Credential API 不可用、网络问题、并发限制旧 AK/SK 过期后不可用

7.8.2 处理策略：三层防护机制

我们采用"主动预防 + 按需触发 + 请求级重试"三层防护机制，而非单一的后台刷新：

图 5：凭证异常处理三层防护机制

7.8.3 各层详细实现

第一层：后台 daemon 刷新线程（主动预防）

  • 每 60 秒检查一次当前凭证是否即将过期（剩余 20% TTL）；
  • 触发刷新时调用 Provider 的 refresh() 方法，内部带指数退避重试（最多 3 次，间隔 1s/2s/4s）；
  • 刷新成功后原子替换缓存凭证；刷新失败保留旧凭证，记录告警日志，下一轮继续尝试；
  • 对于长时作业（>1h），建议在创建作业时通过 duration_seconds 参数请求更长的凭证有效期（最长 12h），减少刷新频次。

第二层：请求前主动检查 + 按需刷新（兜底）

  • 每次业务 API 请求前，AuraClient 内部调用 get_credentials()，该方法会检查凭证是否已过期；
  • 如果已过期（后台线程没来得及刷新），同步调用 provider.refresh() 获取新凭证，然后继续请求；
  • 提供公开接口 client.refresh_credentials()，用户可在长时作业的关键节点主动调用；
  • 同步刷新带超时（10s）和重试（3 次），避免无限阻塞。

第三层：请求级 401/403 自动重试（最终防线）

  • 即使前两层都通过，仍存在竞态：检查时凭证有效，但请求到达 OBS 时已过期；
  • AuraClient 的 HTTP 请求拦截器捕获 401/403 响应，自动触发 refresh_credentials()，用新凭证重新签名并重试原请求；
  • 最多重试 3 次，指数退避（1s/2s/4s）；3 次均失败则抛出 CredentialExpiredError；
  • 仅对幂等请求（GET/HEAD/PUT/DELETE）自动重试，非幂等请求（POST）需用户确认后重试。

7.8.4 长时作业的最佳实践

作业时长推荐配置说明
< 30min默认配置即可（duration=3600s，后台刷新）凭证 1h 有效，作业在过期前完成
30min ~ 2hduration_seconds=7200（2h）+ 后台刷新减少刷新次数，降低失败概率
2h ~ 12hduration_seconds=43200（12h）+ 三层防护单次凭证覆盖整个作业，无需中途刷新
> 12hduration=43200 + 三层防护 + 作业检查点凭证必须中途刷新，依赖三层防护机制；建议作业支持断点续跑
异常处理设计总结

不依赖单一机制。后台刷新线程负责"正常情况下的提前刷新"，请求前检查负责"兜底后台线程的延迟"，请求级重试负责"处理竞态条件"。三层叠加后，凭证过期导致作业失败的概率极低。对于超过 12h 的超长作业，建议在业务层支持检查点（checkpoint），即使凭证完全失效也能从断点恢复。用户可通过 client.refresh_credentials() 在关键节点主动刷新。

7.8.5 AuraClient 异常处理核心代码

class AuraClient:
    def _get_credentials_for_request(self) -> AuraCredentials:
        """请求前获取凭证：第二层防护 —— 已过期则同步刷新"""
        creds = self._credentials
        if creds is None or creds.is_expired():
            logger.info("Credentials expired, refreshing synchronously...")
            with self._credential_lock:
                self._credentials = self._credentials_provider.get_credentials()
                creds = self._credentials
        return creds

    def _request_with_retry(self, method, url, **kwargs) -> Response:
        """第三层防护 —— 401/403 自动刷新凭证并重试"""
        for attempt in range(3):
            creds = self._get_credentials_for_request()
            kwargs["headers"] = self._sign_request(method, url, creds, **kwargs)
            resp = self._http.request(method, url, **kwargs)
            if resp.status_code not in (401, 403):
                return resp
            if attempt < 2:
                logger.warning("Request got %d, refreshing credentials and retrying...",
                               resp.status_code)
                self.refresh_credentials()
                time.sleep(2 ** attempt)
            else:
                raise CredentialExpiredError(
                    f"Request failed with {resp.status_code} after 3 retries. "
                    f"Call client.refresh_credentials() or check Agency / OIDC config.")
        return resp

    def refresh_credentials(self) -> None:
        """公开接口：主动触发凭证刷新（线程安全）"""
        with self._credential_lock:
            self._credentials_provider.refresh()
            self._credentials = self._credentials_provider.get_credentials()
            logger.info("Credentials refreshed successfully.")

08安全设计

8.1 凭证传输与存储

  • 传输加密：所有凭证相关 API 强制 TLS 1.2+；
  • 静态加密：Aura Cloud 侧凭证使用 DEW（华为云数据加密服务）加密存储；
  • 本地存储：~/.aura/credentials 文件建议权限 0600，SDK 初始化时校验；
  • JWT 不落盘：云上 OIDC Token 通过 Projected Volume 挂载在 tmpfs，不写入持久化存储。

8.2 最小权限

  • 信任委托（Agency）的身份策略遵循最小权限，根据用户在 AI DataLake 平台配置的授权范围精确生成；
  • 信任策略严格限定 oidc:sub 为 AI DataLake 专用 SA，禁止通配符；
  • 可选启用 CCE 节点鉴权增强（rbac.kubernetes.io/restricted-by-node: "true"）。

8.3 审计与监控

  • 所有凭证操作（AssumeAgencyWithOIDC、CreateKey、Rotate、Revoke）记录审计日志；
  • 监控 serviceaccount_stale_tokens_total 指标，发现使用过期 Token 的负载；
  • 凭证即将过期提醒：到期前 14 天、7 天、1 天通知。

8.4 应急响应

  • 一键吊销：AI DataLake 控制台支持立即禁用指定 AK/SK 或信任委托；
  • OIDC 提供商失陷：支持临时禁用某个 OIDC 身份提供商；
  • 集群证书更新：AI DataLake 自动监听并更新 IAM 身份提供商的 JWKS 公钥。

10总结

核心结论
  • 云上场景（AI DataLake + 华为云 CCE）：基于华为云 CCE OIDC 工作负载身份机制。AI DataLake 管控面自动获取 CCE 集群 JWKS 公钥、在 IAM 中创建 OIDC 身份提供商和信任委托（Agency）、在 CCE 中创建 ServiceAccount 并配置 Projected Volume。用户提交作业后，CCE 通过 TokenRequest API 签发短期 JWT，Aura Python SDK 调用华为云 IAM STS 的 AssumeAgencyWithOIDC 接口（POST /v5/agencies/assume-with-oidc）换取临时 AK/SK + security_token。ServiceAccount Token 使用短期 TokenRequest 方式（非永久 Secret），kubelet 在 80% 过期或 24h 时自动轮转。
  • 本地 SDK 场景：AK/SK 托管轮转，TOML 双文件配置（AWS 标准），SDK 自动读取与到期前轮转。
  • Python SDK 统一抽象：Provider Chain 4 级链式解析 + AuraClient 统一封装。三层异常防护：后台 daemon 主动刷新（60s 检查，20% TTL 触发）→ 请求前同步检查刷新 → 401/403 请求级自动重试（3 次指数退避）。长时作业建议使用 duration_seconds 延长凭证有效期，用户可通过 client.refresh_credentials() 主动刷新。
  • 安全基线：全链路加密、最小权限、完整审计、一键吊销、集群证书自动同步。
