面向超大规模超节点的 AI DataLake 深度研究合作方案

基于 Ray 统一资源池化与 Aura 多模态数据引擎的逐层协同优化

01研究背景

当前 AI 基础设施正经历一场深刻的架构变革。以华为灵衢为代表的大规模超节点正在成为主流算力形态——通过灵衢高速互联、CXL 内存池化等技术，将数十颗 CPU/GPU/NPU 紧耦合为一个"超级计算机"，节点间通信延迟从微秒级降至纳秒级，互联带宽提升一个数量级。

这一趋势意味着：只有从底向上逐层将系统池化，才能真正释放超节点高速互联的能力。传统"一台机器一个节点"的分布式系统设计，在超节点时代会造成严重的资源碎片和通信瓶颈——紧耦合的硬件被松耦合的软件栈割裂，高速互联能力无法被上层应用感知和利用。

我们的 AI DataLake 产品基于云容器发放异构通算与智算资源（CPU/GPU/NPU），通过 Ray 做统一资源池化管理，在 Ray 之上运行自研的多模态数据处理与向量湖检索引擎 Aura。当前产品已具备基础的 serverless 数据处理能力，但面对超节点浪潮，系统需要向紧耦合 scale-up 与 scale-out 协同的方向深度演进，将 serverless 引擎与分布式框架的协同优化推向更深入的层次。

硬件趋势

华为灵衢超节点规模化部署，CXL 内存池化、芯片间高速互联成为标配，单机算力密度提升 5-10 倍。

软件缺口

Ray 以"节点"为资源单元，无法感知超节点内拓扑；Aura 与 Ray 之间存在语义断层，调度与数据流转各自为政。

合作契机

超节点系统软件是学术界前沿热点，与高校合作开展深度研究，可同时产出学术成果与产品竞争力。

02方案现状

2.1 当前技术栈

  • 资源层：基于云容器发放 CPU/GPU/NPU 异构资源，支持多代次算力混部。
  • 池化层：Ray 作为统一资源调度与分布式执行框架，实现跨节点的资源池化。
  • 引擎层：Aura 自研数据引擎，提供多模态数据处理流水线与向量湖检索能力。
  • 服务层：Serverless 化的数据处理服务，用户按需提交作业，无需管理集群。

2.2 已具备的能力

异构资源统一调度

Ray 已能统一管理 CPU/GPU/NPU 资源，支持自定义资源类型，基础的任务分发与资源匹配可用。

多模态数据处理

Aura 支持文本、图像、音频等多模态数据的摄入、清洗、特征提取与向量化流水线。

向量湖检索

Aura 内置向量索引与近似最近邻检索能力，支持亿级向量的低延迟查询。

Serverless 交付

用户以函数/作业方式提交数据处理任务，系统自动弹性伸缩，按用量计费。

2.3 当前的核心局限

现有架构本质上仍是"节点级松耦合"设计：Ray 将每台物理机视为一个独立节点，Aura 在 Ray 之上做任务调度，两层之间缺乏语义双向传递；数据在远端缓存、Ray 对象存储、进程内内存之间流转时存在重复拷贝和语义割裂；serverless 的无状态弹性与超节点紧耦合作业的需求存在根本矛盾。这些局限在千节点规模下尚可接受，但在万节点超节点集群中会被急剧放大。

03关键挑战

图 C：当前系统六大核心挑战全景示意（红色标记为问题断层）
  • C1
    超节点硬件特性无法被上层感知 Ray 的扁平资源模型无法表达超节点内的 NUMA 域、灵衢互联拓扑、CXL 内存池层次和 NPU 代次差异，导致调度决策缺乏精确的硬件信息输入。
  • C2
    双层调度各自为政，语义断层 Ray 资源调度不理解 Aura 任务的数据流依赖和通信模式，Aura 任务调度不感知底层拓扑和资源碎片，两层独立决策导致"双重碎片化"和通信开销激增。
  • C3
    三级数据流转层语义不统一 远端缓存、Ray 数据系统、进程内内存三层各自管理数据生命周期，对象格式不统一，跨层需序列化拷贝，缺乏流式数据语义和一致性保障。
  • C4
    万节点规模下的控制面与韧性瓶颈 Ray GCS 在万节点规模下面临心跳风暴、调度延迟、故障恢复慢等问题；超节点故障域大，单节点故障影响面广，作业动态迁移能力不足。
  • C5
    Serverless 与紧耦合的根本矛盾 Serverless 追求无状态、细粒度弹性、快速冷启动；超节点紧耦合作业（分布式训练、在线检索）需要长驻进程、低延迟通信、全局同步，两者范式冲突。
  • C6
    Agent 轨迹与多模态数据的引擎能力不足 Agent 轨迹是复杂嵌套 JSON + 多模态字段 + 时间序列 + 图结构的混合体，传统列式存储和向量索引无法高效支撑；复杂 JSON 处理缺乏软硬协同加速。

04总体方案

针对上述挑战，我们提出"从底向上逐层池化、双层调度语义拉通、三级数据流转统一、Serverless 与紧耦合协同"的总体技术路线。核心思想是：让每一层都能感知下层的硬件特性，并向上层暴露精确的语义接口，最终实现超节点内紧耦合 scale-up 与超节点间 scale-out 的高效协同。

整体技术架构如下图所示，自底向上分为硬件层、资源池化层、双层调度层、三级数据流转层、Aura 引擎层，并以 Serverless × 紧耦合协同范式贯穿各层。

图 1：面向超大规模超节点的 AI DataLake 总体技术架构（Excalidraw 风格示意）

架构的核心设计理念是"逐层池化、语义拉通"：硬件层将超节点内的算力和内存池化暴露给 Ray；Ray 资源池化层建立拓扑感知的资源模型；双层调度层通过语义双向传递避免决策冲突；三级数据流转层统一对象模型和流式语义；Aura 引擎层面向 Agent 和多模态场景做深度优化；Serverless × 紧耦合范式贯穿全栈，解决弹性与性能的根本矛盾。

05合作研究方向

基于上述架构，我们提炼出五大研究方向、共 20 项核心课题，按自底向上的层次组织。每项课题均包含明确的研究问题和预期产出，适合与高校团队开展深度合作。

D1超节点异构算力池化与统一编程抽象
图 D1：从扁平资源模型到超节点拓扑感知模型的统一抽象
课题 1.1 超节点感知的异构资源统一抽象与拓扑建模
关键词：Ray 资源模型扩展 · 多维拓扑距离 · 代次画像 · 池化粒度
扩展 Ray 扁平资源描述符，加入 NUMA 域、PCIe 域、灵衢互联距离等拓扑维度，建立多代次 NPU/GPU 的算力/内存/带宽画像，将池化粒度从整机细化到芯片及芯片内切片，为上层调度提供精确硬件信息。
课题 1.2 面向 CXL / 高速互联的内存池化与分层管理
关键词：CXL 内存池 · 多级内存自动迁移 · Ray 对象存储融合 · 超分
研究 HBM→DRAM→CXL 内存池→远端 SSD 的统一管理，实现 CXL 内存的动态分配与超分、基于访问热度的层级间自动迁移、与 Ray Plasma 对象存储的融合，以及 Aura 引擎的内存层级感知。
课题 1.3 多代次异构 NPU/GPU 的统一执行抽象
关键词：统一算子层 · 代次自适应分发 · 异构任务迁移 · 自动并行策略
屏蔽昇腾 CANN 与英伟达 CUDA 等编程接口差异，构建统一算子/任务抽象层，实现代次自适应的任务分发与降级、异构算力间的任务状态迁移，以及基于算力画像的自动并行策略选择。
D2分层协同调度与超大规模集群韧性
图 D2：Aura 任务语义与 Ray 拓扑感知的双层协同调度与联合放置
课题 2.1 Ray 资源调度与 Aura 任务调度的双层协同机制 （核心枢纽）
关键词：双层调度接口 · 语义契约 · 联合放置优化 · 双重碎片化
设计 Ray 与 Aura 之间的语义双向传递接口：Aura 向 Ray 传递任务的通信模式、共置需求、数据局部性等 hint；Ray 向 Aura 反馈拓扑与负载状态。研究联合放置优化算法，避免两层独立决策导致的资源碎片和通信开销。
课题 2.2 拓扑感知的尾延迟优化与 SLA 保障
关键词：尾延迟预测 · 投机执行 · 共置/反共置 · QoS 分级
针对向量检索等在线场景，研究任务级尾延迟预测模型、与超节点拓扑结合的投机执行（straggler mitigation）、通信密集型任务的共置与反共置策略，以及 QoS 分级与抢占式调度。
课题 2.3 万节点级 Ray 控制面的稳定性与扩展
关键词：GCS 水平扩展 · 心跳风暴治理 · 分层调度 · 优雅降级
攻克 Ray 在万节点规模下的 GCS 瓶颈、心跳风暴、调度延迟激增等问题，研究 GCS 分层/分区扩展、增量状态同步、超节点内本地调度+全局调度的分层架构，以及大规模故障下的优雅降级与脑裂处理。
课题 2.4 集群韧性与作业动态迁移
关键词：增量 checkpoint · 无感迁移 · 故障域感知 · 弹性协同
针对超节点故障域大的特点，研究细粒度增量 checkpoint 与快速恢复、运行中作业的无感动态迁移、故障域感知的副本/分片放置，以及弹性伸缩与迁移的协同决策机制。
课题 2.5 多目标全局调度优化（性能 × 成本 × 能耗）
关键词：Pareto 多目标优化 · 功耗感知调度 · 成本弹性 · SLA 平衡
在超节点功耗墙和万节点能耗约束下，研究性能、成本、能耗、利用率的多目标 Pareto 优化模型，功耗/温度感知的超节点内算力调度，以及成本驱动的弹性决策。
D3多级内存与流式数据流转系统
图 D3：三级数据流转统一语义 + 流式共享内存 + RDMA Shuffle 通信
课题 3.1 三级数据流转层的统一对象模型与零拷贝协同
关键词：统一对象模型 · 自动升降级 · 零拷贝跨层 · 生命周期一致性
统一远端 Cache、Ray 对象存储、进程内内存三层的数据对象模型（schema+元数据+引用计数），研究基于热度和访问模式的自动升降级策略、RDMA/共享内存的零拷贝跨层访问，以及跨层数据生命周期与引用一致性管理。
课题 3.2 分布式共享内存与流式数据语义
关键词：可变共享内存 · 生产者-消费者 · 背压 · exactly-once
突破 Ray 对象存储不可变的限制，在其上构建支持增量追加和细粒度共享的分布式共享内存抽象，定义流式生产者-消费者语义与背压控制机制，保障 exactly-once / at-least-once 语义，并与 Aura 流式算子对接。
课题 3.3 大规模 Shuffle 与超节点高速通信优化
关键词：RDMA/灵衢 shuffle · 拓扑感知放置 · 聚合通信 · 不落盘 shuffle
设计基于 RDMA/RoCE/灵衢互联的 shuffle 原语，研究点对点与聚合通信的混合策略、shuffle 数据的拓扑感知放置（减少跨超节点流量），以及与 Aura 执行引擎融合的不落盘 shuffle。
课题 3.4 面向强化学习的 Sample 级数据系统
关键词：Sample 时效性 · 优先级队列 · 生成-训练协同 · 多智能体路由
针对 RL 训练中 sample 生成与消费速率不匹配、sample 时效性衰减的特点，研究 Sample 级优先级队列与时效性管理、反压驱动的探索力度调整、sample 数据的分布式缓存与路由，以及多智能体场景下的数据分发。
D4面向 Agent 与多模态的轨迹数据引擎（Aura 核心）
图 D4：Agent 轨迹数据从复杂摄入到多模态混合检索的一体化引擎流水线
课题 4.1 Agent 轨迹数据的统一模型与存储引擎
关键词：半结构化模型 · 时序+图双重索引 · 增量摄入 · 版本管理
针对 Agent 轨迹"嵌套 JSON + 多模态字段 + 时间序列 + 图结构"的混合特征，设计半结构化统一数据模型，实现时间序列与图结构的双重索引、增量摄入与版本管理，以及轨迹级生命周期与归档策略。
课题 4.2 复杂 JSON 处理的软硬结合加速
关键词：FPGA/NPU 解析加速 · 自动索引 · 行列混合布局 · 查询下推
研究复杂 JSON 解析的硬件加速路径（FPGA/智能网卡/NPU 侧核）、复杂字段的自动索引与物化、列式-行式混合布局（热字段列存、冷字段行存），以及查询下推与谓词下推优化。
课题 4.3 多模态向量湖的统一检索与增量索引
关键词：多度量统一索引 · 混合检索重排序 · 增量更新 · 精度-性能权衡
构建支持多距离度量、多精度的统一向量索引框架，研究文本/图像/音频/视频的多模态混合检索与重排序、向量索引的增量更新与合并策略，以及近似检索的精度-性能-内存三维权衡。
课题 4.4 非结构化数据的解析-特征-检索一体化流水线
关键词：自动解析 pipeline · 特征缓存复用 · 内容级检索 · RAG 质量评估
打通非结构化数据"解析→特征提取→切分→向量化→索引"的全流水线，研究特征提取与索引的协同（增量特征、共享特征缓存）、超越向量相似度的内容级检索，以及多模态 RAG 的数据准备与质量评估。

课题 5.1 有状态 Serverless 与超快速冷启动
关键词：状态外置恢复 · 智能预热预取 · 函数间低延迟通信 · 长短作业混合
解决紧耦合作业对长驻进程和低延迟的需求与 serverless 冷启动的矛盾，研究有状态函数的状态外置与快速恢复、基于作业画像的智能预热与预取、函数间共享内存/RDMA 低延迟通信，以及长作业与短作业的混合调度。
课题 5.2 紧耦合作业的细粒度弹性（不中断并行度调整）
关键词：弹性并行度 · 容错弹性统一 · 快速重连 · SLA 驱动弹性
突破分布式训练等紧耦合作业并行度调整需全局重启的限制，研究不中断训练的 worker 增删、容错与弹性的统一机制、serverless 容器的快速重连与状态同步，以及 SLA 驱动的弹性决策。
课题 5.3 超节点内的 Serverless 算力切片与多租户隔离
关键词：vNPU/MIG 切片 · 带宽/IO 隔离 · 切片间高速通信 · 装箱算法
