# 多模态数据处理运行时拓扑重构课题——Excalidraw 示意图提示词

以下示意图建议统一采用 **Excalidraw 手绘技术架构风格**：

白色背景，黑色粗糙手绘线条，轻微不规则的矩形、圆角框和箭头，中文手写标签，少量低饱和蓝色、绿色、橙色作为重点强调色，无阴影、无渐变、无 3D 效果。整体简洁、技术感强，适合科研汇报、课题立项和专利技术说明。

## 插图 1：从“资源弹性”走向“执行弹性”

**建议放置位置：项目背景章节**

### 图标题

**“从 Resource Elasticity 到 Execution Elasticity”**

### AI 绘图提示词

Create an Excalidraw-style hand-drawn technical architecture diagram.

White background, rough black pencil sketch lines, slightly irregular boxes and arrows, Chinese handwritten labels, muted blue / green / orange highlights, no shadow, no gradient, no 3D.

Title:

“从资源弹性到执行弹性”

Draw TWO large comparison areas from left to right.

LEFT SIDE title:

“传统 Serverless：Resource Elasticity”

Draw a Serverless Controller at the top.

Below it draw:

“业务负载下降”

arrow to:

“期望资源 32 Nodes → 8 Nodes”

Below draw 8 physical node boxes.

Several nodes are lightly filled and labeled:

“低利用率”

“仍有 Actor”

“仍有 Partition”

“仍有运行状态”

Draw a red/orange warning:

“资源想缩，但作业状态还绑定在原节点”

At the bottom write:

“资源可扩缩 ≠ 运行中的作业可扩缩”

Draw an arrow from left side to right side labeled:

“研究突破”

RIGHT SIDE title:

“下一阶段：Execution Elasticity”

Draw:

“运行中的 Dataflow”

inside:

Task  
Actor  
Partition  
Progress  
Object / State

Arrow downward:

“运行时拓扑重构”

Then draw:

Topology T0:

“32 Nodes”

arrow:

“State Rebinding / Online Migration”

to:

Topology T1:

“8 Nodes”

Show released nodes on the side labeled:

“Released”

“重新进入 Serverless 资源池”

Add a highlighted sentence at bottom:

“资源变化，作业执行拓扑也能随之演进”

The visual message should clearly show:

传统 Serverless 主要让资源弹性变化，而新的研究目标是让正在运行的作业本身也具备弹性。

## 插图 3：动态迁移的核心研究对象——从 T0 到 T1 的在线拓扑重构

White background, rough black sketch outlines, handwritten Chinese labels, muted blue / green / orange highlights, no shadows, no 3D.

Title:

“运行中 Dataflow 的动态拓扑重构与在线迁移”

LEFT STAGE title:

“Topology T0”

→

Use dotted lines from logical operators to physical workers to show current mapping.

MIDDLE STAGE title:

“Runtime Reconfiguration”

Draw a central controller:

“Migration Runtime”

Inside it draw three blocks:

“Logical Execution State”

“Consistent Cutover”

“Migration / Recompute / Rebind”

Show actions:

P1 + P2 → Merge

P3 → Rebind

ObjectRef → Rebind

Model Runtime → Reload

Low-value State → Recompute

Draw two large arrows:

“Extract Logical State”

“Re-map Execution”

RIGHT STAGE title:

“Topology T1”

Draw only two Worker boxes:

Worker 5  
Worker 6

Redistribute the remaining logical partitions.

Show old nodes crossed out or labeled:

“Released”

Draw continuous arrows through the whole diagram:

“Dataflow continues”

Add bottom annotations:

“不重启整个作业”

“保留有效执行进度”

“Worker 数量与 Partition 布局可以改变”

“Logical Dataflow 保持连续”

The central visual idea should be:

不是把一个进程从 A 原样复制到 B，而是将逻辑执行状态从旧物理拓扑重新映射到新的物理拓扑。

# 建议的整体插图布局

如果最终材料篇幅有限，可以按照以下顺序使用四张图：

**插图 1：为什么需要 Execution Elasticity**  
解决“为什么要研究”。

↓

**插图 2：为什么多模态 Dataflow 是典型场景**  
解决“这个问题为什么真实存在”。

↓

**插图 3：我们究竟研究什么系统问题**  
解决“Topology T0 → T1 到底是什么意思”。

↓

**插图 4：真正需要突破哪些核心技术**  
解决“我们的技术竞争力在哪里”。

这样整套图的逻辑就会形成：

**Serverless 背景 → 多模态场景 → 动态迁移研究对象 → 三项核心技术突破**

而不会一开始就直接画 Actor Migration，使课题看起来只是一个工程功能。
